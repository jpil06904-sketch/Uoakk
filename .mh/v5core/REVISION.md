# اصلاح چت و رادار مهریار

خروجی قابل انتشار:
- `/workspaces/Uoakk/v5/mehryar-v5.html`
- `/workspaces/Uoakk/v5/panel/api.php`
- `/workspaces/Uoakk/install.php` (حاوی همان API استریم برای نصب و ارتقای پنل)

ساخت مجدد: `python3 /workspaces/Uoakk/.mh/v5core/build.py`
همگام‌سازی API در نصب‌کننده پس از تغییر آن: `python3 /workspaces/Uoakk/.mh/v5core/package_panel.py`
این دستور فقط ماژول V5، پل اتصال چت و CSS را در HTML موجود جایگزین می‌کند؛ نسخهٔ پشتیبان قدیمی را برنمی‌گرداند.
کد رادار اصلی و متن‌های کوتاه ورودی در خود HTML باقی می‌مانند. برای بازسازی این بخش‌ها از HTML قدیمیِ پیش از ادغام، `python3 /workspaces/Uoakk/.mh/v5core/repair_ui.py /مسیر/فایل-کپی.html` اجرا می‌شود؛ این اسکریپت برای اجرای دوباره روی HTML ادغام‌شده نیست.

آزمون‌ها: `check_html.cjs`، `test_core.cjs`، `test_revision.cjs`، `test_budget_scopes.cjs`، `test_radar_ui.cjs`، `test_appearance.cjs`، `test_memory.cjs`، `test_stream.cjs`، `test_net.cjs`، `test_router.cjs`، `test_panel_url.cjs`؛ اجرای هرکدام با Node. PHP نیز با `php -l` بررسی شد. آزمون ظاهر با jsdom فقط DOM و CSS را بررسی می‌کند و جایگزین بازبینی تصویری نیست.
همه‌ی این‌ها با یک فرمان: `python3 /workspaces/Uoakk/.mh/v5core/run_all.py` (بیلد، همگام‌سازی پنل، هر آزمون Node، و آزمون‌های PHP). کد خروج غیرصفر یعنی شکست.
آزمون پنل و CORS: `python3 /workspaces/Uoakk/.mh/v5core/test_api_headers.py`؛ یک نصب واقعی می‌سازد و روی `php -S` درخواست `OPTIONS` با `Origin: null` (همان چیزی که APK با `content://` می‌فرستد) و همچنین خطاهای ۴۰۱/۴۰۰ همان مسیر را با سربرگ CORS بررسی می‌کند. آزمون نشانی: `test_panel_url.cjs` ثابت می‌کند از `content://`، `file://`، `http://localhost` و `android-app://` هم نشانی پنل مطلق و `https` می‌ماند و درخواست نسبی هرگز فرستاده نمی‌شود.
آزمون نصب و ارتقا در پوشهٔ موقت: `python3 /workspaces/Uoakk/.mh/v5core/test_installer.py`؛ نام پایگاه، داده‌ها، فایل بارگذاری‌شده و رمز قبلی بررسی می‌شوند.

محدودیت‌های روشن:
- تست‌های شبکه و IndexedDB محلی شبیه‌سازی‌شده‌اند. دو پیام کوتاه با صفحهٔ فعلی در jsdom و پنل واقعی پاسخ دادند؛ این آزمون جای مرورگر واقعی یا بازبینی ظاهری موبایل را نمی‌گیرد و پاسخ DEEP واقعی را تأیید نمی‌کند.
- تنظیمات API پنل موجود ضدبافر است، اما جلوگیری از بافر پروکسی بیرونی نیازمند بررسی همان هاست است. پنل واقعی در آزمون، بدنهٔ SSE را با سربرگ JSON فرستاد و تکه‌ها تقریباً هم‌زمان رسیدند؛ علت این رفتار تأیید نشده است. صفحه حالا نوع بدنه را بدون ارسال مجدد تشخیص می‌دهد؛ WebView بدون خواندن تدریجی همان پاسخ را یکجا می‌خواند و پاسخ JSON کامل نیز بدون ارسال مجدد پردازش می‌شود. پاسخ خالی پنل قدیمی برای تشخیص امن کافی نیست و خطا نمایش داده می‌شود؛ پنل باید ارتقا یابد. خطاهای داخل استریم، پاسخ ناقص، timeout و خطاهای ۵xx خودکار تکرار نمی‌شوند؛ مدل جایگزین فقط پس از رد درخواست با ۴۰۴ یا ۴۲۹ امتحان می‌شود.
- بودجهٔ ماهانه فقط بازهٔ ماه را مشخص می‌کند؛ محاسبهٔ «دقیقاً چند روز عقب» از آن ممکن نیست. نبود جای کلاس با «اطلاعات کافی نیست» نمایش داده می‌شود.
- اگر برای یک درس بودجهٔ سالانه وجود داشته باشد، همان در تمام ماه‌ها مقدم است؛ ردیف‌های تأییدشدهٔ درس‌های دیگر نیز جداگانه نمایش داده می‌شوند.
- صفحه/فصل نامشخص یا چندپهلو ثبت نمی‌شود. هیچ نگاشت حدسی بین نام مبحث و صفحه ساخته نمی‌شود.
- حافظه، پیام‌های معلمِ موجود در تاریخچهٔ محلی را به IndexedDB منتقل می‌کند و از این پس نگه می‌دارد؛ پیام‌هایی که قبلاً از حافظهٔ گوشی حذف شده‌اند قابل بازیابی نیستند. حداکثر چهار قطعهٔ مرتبطِ قدیمی ارسال می‌شود؛ پاسخ قبلی مدل شاهد واقعیت حساب نمی‌شود.
- اثرات اشتباهِ ثبت‌شده در نسخهٔ قبلی خودکار حذف نشده‌اند؛ معلم می‌تواند آن‌ها را بررسی و اصلاح کند.
- وضعیت جدید جای کلاس بر اساس پایه، سال، نام کلاس و مدرسه تفکیک می‌شود. تنظیمات قدیمی امکانات و حافظهٔ خلاصه همچنان ساختار ذخیره‌سازی قبلی را دارند.
- پیام‌های مرحلهٔ چت با یک تیکِ ثانیه‌ای بازخوانی می‌شوند و فقط متن مرحله را عوض می‌کنند (چرخش اسپینر از نو شروع نمی‌شود). پیام‌های ثابت چت، درخواست روتر را بیش از حدود ۱٫۲ ثانیه متوقف نمی‌کنند؛ بعد از آن، طبقه‌بندیِ فرضیِ متن‌محور انتخاب می‌شود و پیام با یک مرحلهٔ دوم بی‌تأخیر ادامه می‌یابد. مسیر `FAST` در همان تیکر پیام «در حال نوشتن…» را نشان می‌دهد.
- تشخیص پیام خاموش نشده است: هر پیام غیرِ محاوره‌ای از روتر می‌گذرد. فقط عبارت‌های کاملِ احوال‌پرسی و تأیید (مثل «سلام»، «شما؟»، «چطوری»، «مرسی») از روتر رد می‌شوند و روتر برای آن‌ها فراخوانی نمی‌شود. اگر روتر در ۱٫۲ ثانیه جواب ندهد، «کلمهٔ کار» در متن (برنامه، بودجه، تدریس، کلاس، نمره، گزارش و مانند آن) یا وجود «؟» پیام را به `DEEP` می‌برد؛ فقط متن کوتاه و بی‌نشانه به `FAST` می‌افتد.
- زمان‌بندِ استریم حالا «سکوتِ اتصال» را می‌سنجد، نه کلِ زمان را: هر تکهٔ دریافتی مهلت را از نو می‌شمارد (۶۰ ثانیه برای `FAST`، ۱۵۰ ثانیه برای `DEEP`) و یک سقف مطلق ۲۰۰ ثانیه‌ای جلوی اتصالِ بی‌پایان را می‌گیرد. هاست تا ۱۸۰ ثانیه فرصت دارد تا پیش از سرور، خودِ برنامه پیام روشن بدهد.
- پنل برای صفحه‌ای که از `content://` (APK) یا `file://` باز شده، `Origin: null` می‌فرستد؛ پاسخ `Access-Control-Allow-Origin: *` و یک پاسخ ۲۰۴ برای `OPTIONS` دارد تا پیش‌پرواز به مدل نرسد. خطاهای ۴۰۱/۴۰۰/۴۲۹ هم همان سربرگ را دارند، وگرنه WebView فقط «زمان انتظار تمام شد» نشان می‌داد. آدرس پنل همیشه مطلقِ `https` است و اگر روزی نسبی شود، برنامه پیام روشن می‌دهد و منتظر نمی‌ماند.
